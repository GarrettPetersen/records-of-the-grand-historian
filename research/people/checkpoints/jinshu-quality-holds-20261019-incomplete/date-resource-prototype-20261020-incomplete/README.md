# Staging date-resource override — research prototype only

This does not change production scripts. It is an unreviewed design against staging revision `e05f6c66e23741d4f5079e1e04c27f7e2f997490`, not authorization to launch a workflow or change canonical data.

`people-date-resources.mjs` loads a single process-lifetime snapshot when both `PEOPLE_DATE_RESOURCE_ROOT` (absolute) and `PEOPLE_DATE_RESOURCE_MANIFEST_SHA256` (lowercase SHA-256 of exact manifest bytes) are present. Without either variable it returns null, leaving existing root-based behavior to the integration. An incomplete configuration fails. The bundle contains `manifest.json`, `prompt-people-date-review.txt`, and a `schema/` directory. The manifest shape is `{"schemaVersion":1,"schemas":[{"name":"example.schema.json","sha256":"<64 lowercase hex>"}],"datePromptSha256":"<64 lowercase hex>"}`. It requires the exact schema-file set, verifies each schema and the prompt, rejects symlink files, and parses the checked schema bytes. Both consumers use the same snapshot. Other root semantics, including data paths, shared Git queue and lock, remain unchanged.

The adjacent `staging-integration.patch` imports the helper into the staging schema loader and date worker; it assumes the helper is separately included as `scripts/lib/people-date-resources.mjs`. An isolated test of the helper passed eight tests, including missing and mixed resources; `git apply --check` succeeded against exact staged copies of the two modified scripts. The two-file fixture was removed. The full integration, actual staged schema compilation, normal existing workflow tests, offline ownership tests and real packet behavior have **not** been run. The bundle manifest has not been constructed from reviewed staging resources.

The manifest digest is an operator-chosen identity check, not a signature or proof of source authenticity, and does not bind the bundle to a particular script tree, Node dependency version, source, extraction or queue state. A trusted host must establish and record those bindings. Resource selection affects every consumer of the schema loader in that process, not only one chapter, and fails at import if the override is incomplete. The prototype does not solve runner lock handling, independent reviewer ownership or editorial/identity/publication gates. Run no production workflow until all of those issues and the staged-versus-local differences are resolved, independently reviewed and tested. Keep any live or stale locks and recovery artifacts intact.
