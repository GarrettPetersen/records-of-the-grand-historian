## Findings

1. **Publishable analysis output is a latent bypass.** The current production CLI invokes `reconcileExtractionAfterRepairs`, with analysis disabled; the only current import/use of `analyzeReconciliationAfterRepairs` outside tests is the CLI's self-test. Thus no current production caller was found to exploit this. However, the exported analysis API returns the complete `result.extraction`; `analysisOnly` marks the wrapper, not the extraction. On the exact real fixture, analysis returned 13 unanswered unscanned questions, zero unresolved scanned candidates and zero unresolved spans. Passing its extraction directly to `validatePeopleExtraction(..., {strictAliasDispositions:true})` succeeded: 278 units, 822 candidates, 165 people, 695 mentions, 916 claims, 30 repairs, 479 dispositions, zero alias disposition conflicts. A future caller that serializes this extraction could therefore bypass source review while satisfying the extraction validator. Do not deploy as a safely non-publishable analysis API: return only review diagnostics/packet, with no reconciled extraction, and adapt tests without weakening their assertions. This is a demonstrated potential API misuse, not evidence that the current production CLI wrote or accepted it.

2. **Review packet surfaces are proposals, not safe one-span assignments.** On the real current analyzed extraction, s0148's proposed `Bi Lü Hun's father Wei` overlaps separate existing mentions `Bi Lü Hun` (p079) and `father Wei` (p085). A reviewer must decide source meaning and preserve distinct identities rather than treating the full alias as one automatic link. Also s0011 `young Meng east of Wu` overlaps `young Meng`, and s0087 `Gentleman Attendant at the Yellow Gate Zhang Hua` overlaps `Yellow Gate Zhang Hua`; resolution needs explicit overlap treatment. Export does not itself apply these proposals.

3. **Scope of detection is narrower than complete mention coverage.** `reviewUnscannedSurfaces` scans English preferred names and English name-claim values only, in units already associated with a person's mention or claim. It suppresses a found occurrence when any existing mention or scanner candidate fully contains it, irrespective of identity or disposition. Missing aliases, Chinese-only occurrences, occurrences outside those context units, and wrong-person containing spans can escape this supplemental guard; it is not a full-corpus completeness or identity proof. No assertion is made here that a particular missed occurrence is confirmed beyond the s0148 overlap hazard.
