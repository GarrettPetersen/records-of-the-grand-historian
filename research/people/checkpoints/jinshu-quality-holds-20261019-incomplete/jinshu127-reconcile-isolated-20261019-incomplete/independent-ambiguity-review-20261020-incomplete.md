## Blocking interaction

In the attached synthetic fixture, a reviewed prior occurrence of the polity Jin is followed by a second source occurrence `晉軍進` / `The armies of Jin advanced`, and an extracted person's unique preferred name is also `Jin`. The unpatched function copies the prior polity disposition to the second candidate; in this particular example it classifies that occurrence correctly, although copying across units is unsafe in general. The patched function instead reaches the chapter-wide preferred-name fallback and automatically attaches the second candidate as a *person mention*, leaving no unresolved candidate. Both outcomes are automatic; only the latter is wrong on this input. This proves the deletion interacts with later rules and is not uniformly conservative. Conversely, an actual person Jin appearing after the polity may be correctly protected by removing the original shortcut; neither context should be assumed from surface equality alone.

Separately, with the source/English edited in the same unit from the Jin army to `進是一個人` / `The name Jin refers to a man`, remapping retains the previous polity disposition. This limitation predates the patch. The ordinary same-unit test confirms remapping survives a benign prefix insertion, but does not prove semantic safety for arbitrary edited contexts.

## Assessment

The two removals are a useful direction, but this patch is not safe to approve as a standalone general-purpose reconciliation fix while later auto-person fallbacks can turn an ambiguous polity into a falsely linked person. A follow-up should keep ambiguous candidates unresolved before cross-unit alias/preceding-unit/reign-name heuristics, and retain same-unit remapping only where semantic preservation is justified by an explicit review or stricter evidence; tests should assert the desired safety property rather than the current unsafe output. Review other automatic routes and test real packet/validator/publication behavior before applying to staging or using it for a chapter. This is a synthetic independent code review, not a completed corpus audit, chapter approval, or claim that every current alias heuristic is wrong.
