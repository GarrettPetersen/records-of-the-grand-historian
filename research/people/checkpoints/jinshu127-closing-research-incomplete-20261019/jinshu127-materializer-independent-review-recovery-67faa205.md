# Independent materializer review: Jinshu 127

Reviewer: `/root/recovery_review`, separate from the editorial reviewer `/root/disk_audit`. This is an artifact-only review, not authorization to publish or a date or identity approval.

## Findings

1. **The CLI output boundary is not hardened against directory substitution.** It constructs the fixed recovery directory and uses `writeFileSync(..., { flag: 'wx' })`, which protects against replacing an existing final filename, including an existing final-component symlink. It does not verify the real path or prevent a parent directory/ancestor symlink or concurrent substitution, so a hostile or accidental redirected parent could send newly created files outside the intended recovery directory. The tests do not exercise path/symlink cases. Verify host-owned directory ancestry and output targets before any later invocation; `wx` alone is not a complete directory-boundary guarantee.
2. **The four writes are not transactional.** Following a single preflight, the three outputs and receipt are written sequentially. An intervening crash or `EEXIST` can leave a partial set and no receipt; the next run refuses existing targets. Preserve and explicitly reconcile any partial artifacts; do not remove them just to make the script run.
3. **Pinning and provenance have limits.** The script checks only its five top-level imported modules itself, not their transitive imports, glossary, runtime, or external witness. The independent inspection below verified the current transitive static relative module closure and glossary, but that is not an ongoing guard against subsequent drift. The editorial witness is a live third-party page, not immutable hashed evidence, and the original extraction's complete author identity cannot be inferred from null metadata. The independent reviewer conversation is distinct from mine, but author independence cannot be machine-proved from those null fields.
4. The file calls itself offline-only, but its CLI makes two network `git ls-remote` checks. The exported pure function and its offline tests do not need those checks. The check is a snapshot, not a lock on staging after it succeeds. Recheck all publication prerequisites immediately before any host-owned publication.
