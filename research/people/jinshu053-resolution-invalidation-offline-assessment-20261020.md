## Supported invalidation and offline test

The existing extraction replacement path `writeAcceptedExtraction` invokes `invalidateResolutionReferences` for the whole changed chapter when serialized extraction differs. Its pure helper `pruneResolutionDocument` removes all target-chapter local-person references from each decision, removes decisions with fewer than two remaining people, and removes canonical pins from shortened decisions. `pruneResolutionPeople` exists for the distinct false-person removal workflow, not as an approved semantic-change classifier for extraction replacement. Resolution documents have no source or extraction fingerprint or explicit source-evidence dependencies; the production resolver consumes their local IDs directly.

Applying the existing whole-chapter pure helper in memory to the 80 matching documents at the pinned staging revision touched 595 decisions and removed 595 target references. Of these decisions, 337 were removed and 258 shortened. All 80 serialized results round-tripped to the same JSON and passed the pinned fixture's resolution schema; 125,196 unrelated decisions in those same files remained byte-equivalent as JSON values. This does not exercise the global identity resolver, detect semantic contradictions, validate every historical note, or prove the resulting catalog and site. The helper retains descriptive notes when shortening a multi-person decision: notes can still mention a removed person and should be reviewed instead of treating schema success as sufficient.

An exploratory projection compared normalized person records, mentions, outgoing and incoming claims, and complete referenced source units, ignoring generated claim/mention IDs. It found changed local IDs p001, p003, p026, p038, and p056; p038 is included because the prince's letter attribution claim c0516 names her and cites the changed units. A person-only pure prune would touch 38 decisions across 15 files, removing six and shortening 32. This is a useful review-scope diagnostic, **not** a safe substitute for the supported whole-chapter rule: old decisions have no sealed dependency lists, and a reviewer could have used chapter context not captured in that projection. A person's own unchanged extraction projection does not prove an old identity decision's underlying evidence was unaffected.

The observed empty 053 extraction and date entries in the queue are only a point-in-time observation; there is no demonstrated general editorial/identity fencing token here. Do not steal leases or remove locks. Recheck remote refs, all original input hashes, and ownership immediately before publication; a Git expected-parent/CAS protects only staging ref movement, not independent future writers.
2. Against the exact refreshed staging tree, preserve the original 80 resolution files and complete old date report in Git/history or immutable tracked research, generate the supported chapter-wide pruned documents in isolated artifacts, and independently audit retained multi-person notes and decision semantics. Invalidate changed 053 references and enqueue source-backed fresh identity review; preserve all unaffected decisions and do not infer replacement merges.
3. Prepare the source, extraction, authentic editorial history, pruned resolutions and a truthful, freshly fingerprinted date state in one coherent alternate-index tree. Existing `research-blocked` date report becomes stale when the candidate changes; date verification fails stale reports. Archive old evidence using the documented recording process and obtain a real fresh independent report or explicitly retain the unresolved work under the supported workflow. Never copy old approvals onto changed fingerprints. Rebuild all shifted claim-ID packets and validate any other dependent references. The version-4 editorial history is authentic, but the overall chapter remains editorially open.
4. Before pushing, perform source-pinned integrated scoped validation, resolution schema and global identity consistency checks, and the relevant date verification using a safe staging-equivalent environment. Because disk is below 30 GiB and the shared checkout has a materially different dirty schema, no full checkout, global build or shared-file replacement is authorized here. Publish the atomic reviewed Git tree only after all ownership, packet, stale-audit and identity safeguards are satisfied, with CAS against the actual staging parent. Push is a partial-work checkpoint, not chapter completion or master release.

The present offline work establishes the supported mechanism and impact but does not establish an atomic staging transition is safe now. No source, resolution, date, queue, lock, index, branch, worktree or build was changed.
