## Risks requiring attention before application

- In the observed checkout `scripts/sdk-people-editorial-review.mjs:301–330` first tries `validateEditorialDecisions(existing, loaded.extraction, loaded.packet)` when accepting a new review. If the existing history has a different proposal set, that current-proposal check fails; the code archives the previous file as stale and stores the incoming document, instead of merging the old review into the active history. Archiving is not equivalent to retaining prior approvals in the active history. Do not use that acceptance path blindly for a fresh 053 proposal set. Independently test or fix the host's history-preservation behavior before committing a genuine review.
- `scripts/apply-people-translation-repairs.mjs:2054–2260` always chooses the canonical chapter with `chapterPath`. Passing `--extraction` only changes the extraction file; a normal application still writes the canonical chapter and packet, and writes chapter, extraction and packet sequentially.
